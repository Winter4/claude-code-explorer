# Claude Code Explorer (cce)

CLI/TUI-утилита для менеджмента и синхронизации сессий Claude Code между машинами.

Проект пишется «в общем виде»: никаких захардкоженных путей, репозиториев и юзернеймов — всё настраивается пользователем.

## Цели

1. **Обозреватель сессий** — удобный TUI для просмотра, чтения, редактирования метаданных, удаления и поиска сессий Claude Code.
2. **Синхронизация** — перенос сессий между машинами через git-репозиторий пользователя, с возможностью продолжить сессию (`claude --resume`) на другой машине.

## Исходные данные: как Claude Code хранит сессии

- `~/.claude/projects/<encoded-cwd>/<session-uuid>.jsonl` — сессия, append-only JSONL, одна строка = одно событие.
- `~/.claude/projects/<encoded-cwd>/<session-uuid>/` — вспомогательные данные сессии (`tool-results/` и т.п.).
- `~/.claude/file-history/<session-uuid>/` — снапшоты файлов для `/rewind`.
- `~/.claude/sessions/<pid>.json` — живые процессы claude (позволяет понять, какие сессии сейчас активны).
- Сообщения образуют дерево через `uuid` / `parentUuid` — отсюда форки и ветки; субагенты помечены `isSidechain`.
- `<encoded-cwd>` — абсолютный путь с `/` → `-`. Кодировка с потерями, источник истины — поле `cwd` внутри записей.
- Формат не документирован и меняется между версиями (поле `version`) — парсер должен быть толерантным к неизвестным типам и полям.

## Идентификация проекта

Claude Code привязывает сессии к абсолютному пути. Для cce один и тот же проект на разных машинах (`/home/user/projects/x` и `/home/another/work/x`) должен быть одним проектом — **высокий приоритет**.

Стратегия идентификации (MVP):

- **Маркер-файл** `.cce` с UUID проекта в корне проекта. Обязателен и коммитится в репозиторий пользователя — так идентификатор приезжает на любую машину вместе с `git clone`.
- Работает и для вложенных папок с одним общим родителем (например, `group/` — группа в GitLab, а не репозиторий; `group/devops/` и `group/server/` — отдельные проекты со своими `.cce`).

Если локальные данные не соответствуют данным в облаке (юзер влез руками и изменил `.cce`), пока что просто показываем ошибку. Детальный хэндлинг такого случая пока что NOT IMPLEMENTED.

## Обозреватель (TUI)

- `cce` — сессии текущего проекта; `cce --all` — все проекты.
- Список сессий: заголовок, дата, ветка git, размер, статус (активна / нет).
- Действия: resume (запуск `claude --resume` в нужной папке), fork, экспорт в markdown, удаление/архив, переименование, теги.
- Редактирование — **только метаданные** (название, теги). Содержимое сессий (сообщения) cce никогда не изменяет.
- НА БУДУЩЕЕ: Предпросмотр сессии, продвинутая читалка сессии, markdown-рендер, сворачиваемые вызовы инструментов, отображение веток/форков, субагентов.
- НА БУДУЩЕЕ: Полнотекстовый поиск (в проекте / глобально).

## Синхронизация

- Через git-репозиторий пользователя (GitHub/GitLab/любой). Git вызывается как внешняя команда — используются уже настроенные у пользователя SSH-ключи / credential helper, cce сам ключи не хранит.

Всё что ниже - наброски, НА БУДУЩЕЕ, 99% будет дорабатываться\меняться. Не входит в MVP
- `cce sync init` — спрашивает URL репо, проверяет доступ и приватность.
- Структура sync-репо: `projects/<project-id>/…` + метаданные машин.
- Переписывание путей: при push абсолютные пути → плейсхолдеры (`{{PROJECT_ROOT}}`, `{{HOME}}`), при pull — обратно в локальные; файлы раскладываются в правильный `~/.claude/projects/<encoded-cwd>/`.
- Конфликты: сессии append-only — если одна версия префикс другой, берём длинную; при расхождении сохраняем обе (одна становится форком). Данные не теряются.
- Активные сессии не синхронизируются.
- Автосинк через хуки Claude Code (`SessionStart` → pull, `SessionEnd` → push); `cce hooks install` прописывает их сам.
- Безопасность: сессии содержат секреты (env, токены, прочитанные файлы) → репозиторий строго рекомендован приватным (проверка + предупреждение). Шифрование — см. «После релиза».

## Установка и дистрибуция

- Установка без пакетных менеджеров, по аналогии с nvm: `curl … | bash` → бинарь в `~/.cce/bin`, PATH в rc-файле шелла.
- `cce update` (само-апдейт)
- Релизы под linux/macOS/windows (amd64/arm64) через goreleaser + GitHub Actions.

## Стек

- **Go** — один статический бинарь без рантайма, кросс-компиляция, быстрый старт (важно для хуков), производительность для парсинга больших JSONL.
- **Bubble Tea / Bubbles / Lip Gloss** — TUI; **Glamour** — рендер markdown; **Huh** — формы/визарды; **Cobra** — подкоманды и флаги.

## Фазы

MVP:

0. **Разведка** — описание формата JSONL, фикстуры из реальных сессий разных версий.
1. **Ядро** — парсер, индекс проектов/сессий, идентификация проектов через `.cce`, конфиг, хранилище метаданных (названия, теги).
2. **TUI** — список сессий (текущий проект / все), статус, действия: resume, fork, экспорт в markdown, удаление/архив, переименование, теги.
3. **Дистрибуция** — install-скрипт, релизы, `cce update`.

После релиза — см. следующий раздел.

## После релиза (не входит в MVP)

1. **Синхронизация + шифрование.** Синхронизацию без шифрования нельзя выпускать, потому что нельзя полагаться на то, что юзер будет хранить данные в приватном репо. Нельзя допустить утечки данных через наше приложение, это дилетантство, а мы профессионалы.
   - Заметка: git плохо сочетается с шифрованием — дельта-сжатие не работает, зашифрованный файл при любом изменении выглядит полностью новым (сессия 1 МБ × 20 синков ≈ 20 МБ). Решение: сессии append-only → шифровать и пушить только новые чанки.
   - Заметка: ключ нужно доставить на каждую машину (пароль или файл ключа при `cce sync init` на второй машине) — неизбежный шаг UX.
2. **Работа с `.cce`, который не коммитится** в репозиторий юзера (gitignore / глобальный gitignore / хранение привязки в `~/.cce/`).
3. **Идентификация проекта через Git remote** — нормализованный URL remote (+ относительный путь от корня репозитория для вложенных проектов).
4. **Продвинутая читалка** — предпросмотр, markdown-рендер, сворачиваемые вызовы инструментов, ветки/форки, субагенты.
5. **Полнотекстовый поиск** — в проекте / глобально / по всем машинам.
6. **Статистика** — токены, модели, время; сравнение сессий.
